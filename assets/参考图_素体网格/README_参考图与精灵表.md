## 〇、8 张 = 8 个方向

和上一轮的 G5 不同，这 8 张是**每张固定一个方向、格内是该方向的动作相位**——标准 8 向等距 turntable 矩阵，不是「一张图里混着多个方向」。

| 方位 | 板 | 帧数 | 置信 |
|---|---|---|---|
| N 正面 | H6 | 32 | 中 |
| NE 右前斜 | H2 | 32 | 中 |
| E 右侧 | H3 | 32 | 高 |
| SE 右后斜 | H7 | 32 | 中 |
| S 背面 | H8 | 32 | 中 |
| SW 左后斜 | H5 | 32 | 中 |
| W 左侧 | H4 | 32 | 高 |
| NW 左前斜 | H1 | 32 | 中 |

**判读方法**：每张取 r2c2 代表格放大目视——两侧都能看到耳突 = 正/背，单侧耳突移到视野中间 = 3/4，单侧耳突贴轮廓且见侧面脸线 = 纯侧；并量了头部逐行左右边界的外凸行数作旁证（H1 左凸 32 行 / H2 右凸 32 行 / H6 两侧均有 / H8 两侧均有）。

**只有 E / W（纯侧）置信度高**，因为轮廓不对称最明显。这批白模**没有五官**，N/S 只能靠耳突高低与躯干细微差区分，四个斜向还要判「前斜 vs 后斜」。原始素材没有任何方位标注。置信度在 `manifest.json` 的 `direction_inference.confidence`、罗盘矩阵图、网页方向表里四处一致。

**改名成本很低**：若实际朝向与推断不符（最常见是 H6/H8 的 N↔S 对调，或「左/右」按观察者而非角色自身），只改 `build_sheet.py` 的 `DIRECTION` 里对应 `dir8` 一处即可，裁帧、配色、manifest 结构与资产帧全部不受影响。

## 三、绿幕和之前「绿特别多」不是一回事

| | 之前被你打回的生成板 | 这 13 张 3D 白模网格 |
|---|---|---|
| 绿 | 模型把绿画进绒毛/阴影，杂色、抠不干净 | **纯 `(0,255,1)` 标准色键**，四角即该值 |
| 抠像 | 15533 px 残留，需事后补 | 裁出 **412 帧，可见区绿残留 1 px** |

绿幕本身没错，错的是生成模型把绿当笔触画进图里。3D 渲染给的是干净色键，正好是 GenioPlus 工作流第 1/3 步（去背→合成绿幕→拆帧色键）的标准输入。生产资产仍坚持米底/透明底，不加绿。

这接上 GenioPlus 的 **序列帧动画**（一张图→待机/行走/攻击）与 **3D 模型→精灵图**（免费，上传已绑定 GLB，浏览器用自己的 GPU 渲染 4/8/16 方向）。

## 五、如实说的限制

1. **自有资产仍只有 N（正面）1 向**，其余 7 向 0 张，已写进 `gaps` 而非编造。补齐最短是 GenioPlus 免费「3D→精灵图」（需已绑定 GLB），或按这批白模逐方向补生成厚涂版。
2. **方位名是推断不是标注**：白模无五官，只有 E/W 纯侧可高置信判定；N/S 的正背、四个斜向的前后归属、以及「左/右」按角色自身还是观察者，都未经原素材确认。改 `DIRECTION` 一处即可整体改名。
3. **两批白模不是同一个模型**：A 批是光滑圆头，B 批头侧多了小耳突；比例与光照也略有差异。只借姿态、方向与网格组织，不混用像素。画风锚仍是历史厚涂母版。
4. **64 件 ≠ 64 个连续动作帧**：16 体形/服装候选 + 16 配件 + 16 少女版配件 + 8 毛色 + 8 动作。真姿态只有 8 帧，和 B 批 32 帧/方向的密度差距还在。
5. B 批白模上下行几乎贴着、粘连比 A 批更重，裁切按「质心最靠近格中心」取域；个别帧带一点相邻白模残片或缺一截指尖，仅作参考，不影响装配资产。
6. 这 13 张版权来源不明，**只作参考与结构比对**，不进 `dist/`、不作图生图底图、不对外发布。你自有原图的授权台账仍建议补齐。
7. 绿残留合计 **1 px**（非 0）：JPEG 压缩在白模边缘产生的一颗过渡像素，逐帧留痕，没抹成漂亮 0。
8. 全量网页 15.79MB，手机可能吃力；**优先开 `八方向_速览.html`（1.54MB）**，要逐帧看再去全量页。
