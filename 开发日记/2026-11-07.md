## 09:52　立项：把 纸娃娃4.0 的操作模型搬成自己的

**要解决什么**

参考站 `mxd.dvg.cn/zhiwawa_v4` 的纸娃娃交互好用，但它的贴图是别人家的游戏美术。要一套能长期用、能改、能进自己项目的同类工具。

**怎么做的**

- 只复刻**交互模型**，不复制图片与代码。站点是 Vite 打包的 SPA，读它的资源清单和界面文案，拆出四步流程（存档/装扮/画布/就绪）、槽位键、导出项，写成 `操作模式_对照表.md`。
- 素材换成自有资产：`单源版` 11 层骨架（1328×1776 同画布，零偏移可叠）+ `八向资产` 8 向 × 4 帧（160×190）。
- 渲染自己写：单 canvas，图层数组顺序 = 合成顺序，支持每层显隐/透明度/上下移。
- 相机用「适配比例 × 用户缩放 + 平移偏移」，滚轮缩放、拖拽平移，导出时走另一条离屏路径不带动画状态。

**验证**

- 11 层 alpha 合成与原图逐像素对比：manifest 声明 `alpha_diff_max = 0`，复核成立（底图是 RGB 带奶油色底 217,205,192，直接比 RGB 会误判）。
- 浏览器打开 `index.html`，4 个标签、11 槽位、缩放导出均可用。
- 八向帧模式的实际渲染**未验证**：浏览器截图接口返回 `display surface not available`，代码路径只做了静态审查。

**坑**

- 中文路径在 `img.src` 里必须 `encodeURI`，直接拼会 404。
- 参考站资源直连返回 403，带 `Referer` 才给；分析完立即删掉，不留别人的 bundle 在仓库里。
- 窄窗口（345px）下三栏布局把画布挤没了 → 加断点，1180px 以下侧栏改成抽屉。

**要解决什么**

仓库要公开，且以后每次改动都能同步。本地提交早就好了，卡在推送。

**怎么做的**

- 没有 `gh`，创建远端走 GitHub API（`POST /user/repos`），仓库名 `hashimiao-paperdoll`，公开。
- 推送一直 `CONNECT tunnel failed, response 502` 或 `OpenSSL SSL_read: unexpected eof`。本机走的是 `127.0.0.1:52507` 代理，短连接时通时不通，长连接基本必挂。
- 对策不是硬重试，而是**把历史拆成 7 个小提交**，每段单独推：代码文档 370KB → 八向帧 15MB → 骨架层 23MB → 配饰 18MB → 参考图三批。每段推完用 `ls-remote` 比对 HEAD，不一致就重试该段。

**验证**

- 远端 `main` HEAD 与本地一致（`c5e933b`），工作区干净，7 个提交全部落地。
- `private: false`，默认分支 `main`。

**坑**

- `git ls-remote` 成功不代表推送成功，两者走的连接时长不同；判断推送结果必须比 commit sha，不能看「没报错」。
- 拆分提交不只是为了网络：以后 clone 的人看历史也清楚哪批资产是哪一步加的。

## 11:05　复核 Pages

**要解决什么**

站点上线后，内置浏览器打开是空白画布，只有中间一个白点。要判断是站点坏了还是本地网络坏了。

**怎么做的**

- 直接查资源响应头：`HTTP/1.1 200`，`Content-Length: 2131211`，`Content-Type: image/png`，`X-Cache: HIT`，GitHub CDN 正常吐出 2MB 完整图。
- 同一 URL 用 curl 下载，一次拿到完整 2.1MB，另一次在 144KB 处被截断（exit 28）。

**验证**

- 资源本身正确、缓存命中说明 CDN 侧已部署完整。
- 结论：空白是本地代理截断大响应导致图片解码失败（`naturalWidth = 0`，画布按设计静默跳过），**不是站点问题**。
- 用内置浏览器完成的视觉验收不成立，改用响应头 + 字节数判定。真实观感需在用户本机浏览器确认。

**坑**

- 图片加载失败时代码里是静默跳过，画面上只表现为"没画东西"，很容易误判成渲染 bug。这种静默容错值得加一个控制台告警。
